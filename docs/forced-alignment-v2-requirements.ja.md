# 音響時刻再整列 v2: 要件

## 目的

日本語学習者の回答音声について、文字起こし範囲と発話時刻の対応候補を、現在のCTC argmax時刻より信頼できる形で作れるか検証する。主用途はInteractionの回答候補区間であり、発音の良し悪しやCEFRの採点ではない。

## 維持する契約

- 共通 `evidence.v1`、現行 `transcript-alignment.v1`、Fluencyを含む5モジュールの既存出力、Judge入力、AI呼び出し回数は変更しない。
- 共通層と客観モジュールでLLM採点はしない。音響モデルの使用と「AI評価」を区別する。元音声をJudgeに渡さない。
- 新方式は初期状態で無効にし、失敗しても旧経路を使える。結果は候補であり、設問・話者・回答を自動確定しない。
- 正規化した文字列・モデル版・時刻算出法・音声ハッシュ・状態・失敗理由を記録する。未対応文字を黙って捨てない。
- Macで検証し、AWSで再現可能な依存関係・ライセンス・資源使用量を確認する。音声と人手注釈は外部サービスへ送らない。

## 成功判定

人手注釈した同じ学習者音声で、現行時刻、CTC再整列、必要に応じて日本語対応の別モデルを比較する。回答区間の開始・終了の誤差分布、対応率、失敗率、推論時間、メモリを測る。採用可能な許容誤差はベンチマーク前に用途別に決め、結果を見てから都合よく変更しない。
