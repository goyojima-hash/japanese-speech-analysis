# 観測・基準変換の独立検証（オフライン再実行）

## 要件

- 保存した設問・確認済み回答・観測結果を使い、観測と基準変換を別々に検証する。
- 通常API・対話CLI・共通Evidence・５モジュール・従来CEFR結果は変更しない。
- 音声送信、モデル呼出し、自動的な設問対応推測は行わない。
- 正解ラベルがない場合は精度を算出しない。特定の設問の正式基準は作らない。
- 入力、モデル来歴、基準版、判定不能を保存し、あとで同じ観測を再検証できる。

## 設計

独立した `task_assessment_replay.py` を評価層の検証ツールとして追加する。
入力は `cases` 配列。各ケースは一意な `case_id`、共有 `transcript`、
`duration_sec`、既存形式の `task_context`、設問IDをキーとする保存済み
`observations`、任意の `labels` を持つ。回答対応は既存 `TaskContext` で検証する。
観測は既存 `TaskObservation` の引用照合を通し、基準変換は既存
`assess_shadow_tasks` / `apply_rubric` を再利用する。

ラベルは設問ごとに `observation`（act_type / target / features の任意の非空部分集合）と
`rating` を別々に指定できる。観測ラベルは人が確認した行為の正解であり、
ASRの正確さの正解ではない。引用照合に成功しても意味が正しいとは限らない。
rating は同じ設問・回答単位の正解のみ。録音全体の従来task_ratingを流用しない。
ラベル作成者・出典などはケース内のメタデータとして記録できるが、本ツールは
その真正性を保証しない。実データの採用判断には別途人手確認が必要。

観測精度と各基準版の達成度一致率を分ける。分母は正解付き設問の全件数で、
欠落・無効観測・ルール未一致・競合も除外しない。予測を出せた件数を別に示す。
ラベルがゼロなら accuracy は null。型の違い（true と 1）も不一致とする。
同一rubric_idの複数versionを明示的な別ファイルとして読み、同じ観測を再適用する。
通常運用の基準レジストリには登録しない。複数設問には該当rubric_idの版だけ適用する。

出力は入力全体のSHA-256、検証済み観測、設問別ステータス、基準の来歴と版、
比較指標。入力ファイルと同じ出力パスは禁止し、入力は上書きしない。
APIキー・音声は不要。個人情報を含む文字起こしはローカルで適切に管理する。

## タスク

1. 正解なし、観測失敗、未確認対応、版比較、複数設問、入力拒否、CLIのREDテスト。
2. 保存済み観測の検証・版別再実行・独立指標の最小実装。
3. 新規コード80%以上のカバレッジ、既存全テスト、lint、依存監査。
4. 操作例をREADMEに追加。合成テストを実データの精度実証と呼ばない。
