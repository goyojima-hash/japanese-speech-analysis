# 対話コンソールのEvidence出力 不具合レポート

## 問題

対話コンソールは共通の `EvidenceBundle` を生成していましたが、その客観データを表示していませんでした。また、Fluency/Range のみだった古い実行順を保持していたため、実装済みの Accuracy モジュールを呼び出さず、Judge にも `accuracy_data` を渡していませんでした。API の選択経路は正しく、CLI 経路だけが未統合でした。

## 再現根拠

1. `./open_jgrade_console_terminal.command` を起動し、音声を選択します。
2. コンソールが `[1/5] Fluency`、`[2/5] Range` の後に直接 `[3/5] Judge` へ進むことを確認します。
3. `=== 共通Evidence層客観データ ===` と `=== Accuracy客観データ ===` のどちらも表示されないことを確認します。
4. 新しい対話コンソールの集中テストを実行します。修正前は、捕捉した Judge 入力で `KeyError: 'accuracy_data'` が発生します。

## タイムライン

- Evidence v1 を共通の事実層として統合しました。
- Accuracy を追加し、API 経路では選択可能にしました。
- 実際の Terminal 実行で、対話経路が旧来の二つのモジュール順のままであることを発見しました。
- 本番コードを変える前に、集中テストで `accuracy_data` 欠落を再現しました。

## なぜなぜ分析

1. なぜコンソールに Accuracy がないのか。`run_interactive` が `AccuracyModule.collect` を呼んでいません。
2. なぜ呼んでいないのか。API 統合後もコンソールが古い Fluency/Range 実行順のままでした。
3. なぜ共通Evidenceが見えないのか。生成済み `EvidenceBundle` をコンソール表示する処理がありませんでした。
4. なぜテストで見逃したのか。既存の対話テストは Range 入力と段階表示だけを検証していました。
5. なぜ不十分なのか。客観パケットが生成され、表示・後段転送されなければ、コンソール利用者にモジュールは提供されていません。

## 特性要因図

- **コード:** API と対話コンソールで事実パケットの組み立てが重複していました。
- **統合:** Accuracy は API 経路にだけ接続されていました。
- **表示:** 共通層の簡潔なCLI表示がありませんでした。
- **テスト:** 対話契約に Accuracy と共通層の確認がありませんでした。
- **プロセス:** 実 Terminal のスモークテストが、コンソール統合検証の後になっていました。

## 修正と再発防止

- Bundle 生成直後に、共通Evidenceの簡潔な事実要約を一度だけ表示します。
- 同じ Bundle から Range と独立して Accuracy を実行し、事実パケットを表示して Judge 入力に渡します。
- 3つの事実モジュールの後に Judge と協議が続くよう、コンソールの段階番号を更新します。
- 新しい集中テストで、共通/Accuracy の見出しと Judge 境界の `accuracy_data` を固定します。
- コンソールの再起動前に、集中・全体・コンパイル・差分チェックを再実行します。
