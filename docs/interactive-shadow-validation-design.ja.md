# 通常ターミナルでの任意並行検証

## 要件

検証は既定OFF。開始画面で利用者が明示的にONにした場合だけ追加処理を行う。
通常CEFR・５モジュール・協議結果を変更しない。OFFなら基準読込・観測AI呼出し・
検証保存は行わない。APIとevaluate-speechの既定offも維持。

## 設計

ON/OFFの選択前に、検証対象を明示する。①行為・対象・特徴を観測して引用を照合、
②登録済みの項目別基準で達成度へ変換し適用ルールと版を記録。
両段階は後から人の確認結果と比較するために分けて保存する。
設問・回答対応が未確定なら保留、基準なしなら観測のみ。
人手正解がない段階では精度を算出しない。表示変更のみで既定OFFを維持する。

通常評価の表示後に、別枝で既存TaskContext / TaskObservation / assess_shadow_tasksを使用。
観測には通常Judgeで選択した最初のprovider/modelを使用し、追加費用と最大20秒の
呼出し待ちが発生し得ることをON選択時に知らせる。音声は送らない。
mockは観測を作らずmock_unavailable。設問なしや回答対応未確認は保留。
単一設問ならASR抽出後、録音全体をその回答とするか明示確認する。
複数設問は既存の確認済みanswer_segmentsがある場合のみ観測し、未確定なら保留。
設定を永続化せず、起動するたびOFFに戻る。Enter/EOFはOFF。

結果は通常履歴のprediction_history内のtask_validationに別保存する。
OFFならそのフィールドは追加しない。新結果を人手正解・正式精度として扱わない。
ON時は保存先と文字起こしが記録されることを知らせる。保存無効時は表示のみ。
基準読込・コンテキスト検証・観測失敗は検証結果として記録し、通常結果を失敗させない。

- 新規9テストを含む203テスト成功。
- 検証ヘルパーの行カバレッジ100%。追加コードのlint成功。
- 対話経路のOFF/ONで通常CEFR・達成度・客観データ・Judge結果が一致。
  観測失敗時も通常結果を維持し、別の検証状態を保存。
- OFFで基準読み込み、確認入力、観測呼び出しなし。Enter/EOFはOFF。
- 既存の設問入力編集のうち、検証に必要な設問取得・共有のみを統合。

  達成度は保留。複数設問の対応・基準指定は既存API/evaluate-speechで明示できる。
