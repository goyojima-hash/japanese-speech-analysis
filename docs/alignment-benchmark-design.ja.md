# 音響時刻の比較検証: 設計

## 入出力

`jgrade_eval/alignment_benchmark.py` は、人手注釈の検証と時刻誤差の計算だけを行う。`jgrade_eval/alignment_benchmark_cli.py` は `prepare` と `evaluate` を提供し、モデル推論はprepareだけで実行する。

保存先は指定する新規ディレクトリ。既存保存先へのprepareはエラーとして、修正済み注釈を上書きしない。`predictions/` に同じ推論から得た2方式と従来の生モーラ時刻、`references/` に正解入力用JSON、`manifest.json` に対応関係を保存する。失敗したファイルはprepareを成功扱いにせず、そのエラーを表示する。途中の保存先は検証に使わず、prepare完了のmanifestがある場合だけevaluateする。

正解JSONは音声ハッシュ、録音長、ひらがな文字起こし、録音形式、文字起こし確認者、対象区間を持つ。各区間は文字範囲、正解start/end秒、確認状態、確認者を持つ。機械の提案時刻は`suggested_start_sec/suggested_end_sec`、正解時刻は`start_sec/end_sec`。初期値はpending/nullとする。候補はCTC時刻の0.5秒以上の空白でまとめるが、その区切りを設問や対話ターンと認定しない。必要に応じて人が範囲を修正・追加する。

## 比較規則

音声ハッシュと文字起こしが一致し、文字起こしと区間がreviewed・human・確認者付きの場合に評価する。各方式で文字範囲を完全に覆う連続単位が必要。未対応、無効時刻、音声違い、文字列違いは理由付きの未採点区間として報告する。goldの無効時刻、重複ID、範囲外の文字はエラーにしてデータ修正を促す。

誤差は`推定-正解`の符号付き秒差から計算する。開始/終了/合計について絶対誤差分布を報告する。許容幅内の割合は「採点できた境界だけ」と「全正解境界」を両方出す。片方の方式が難しい区間を保留することで見かけの精度が上がる場合を確認できる。録音形式別にも集計する。未入力ファイルはpending_referenceとして示し、精度ゼロや精度100%に置換しない。

文字起こしを人手修正すると過去の予測はincompatibleになる。その際は新しい文字列で別の実験を作り、ASR条件と人手逐語条件を分けて比較する。MFA/WhisperXは将来同じ予測スキーマへ変換できるが、今回追加する方式は現行2方式だけ。

## 検証

既知の時刻を持つ合成fixtureで誤差・分母・閾値境界を検証する。pending注釈、文字列違い、音声違い、時刻不正、方式保留のテストを先に用意する。実音声3件はprepare/evaluateの疎通確認に使い、正解未入力のまま精度を報告しない。5モジュールとJudgeの既存回帰テストを実行する。
