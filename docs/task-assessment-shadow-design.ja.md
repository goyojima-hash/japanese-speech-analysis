# 発話行為観測と項目別達成度の分離・検証

## 要件

特定の設問型や開発用サンプルを前提にせず、同じ録音について「何を発話したかの推定観測」と「設問別基準による達成度への変換」を別々に記録・検証する。

- 共通Evidence層と５つのFact Moduleは客観データだけを出し、LLM評価を含めない。
- 既存Judgeの `task_rating` と `final_cefr_level` は維持する。新経路は明示的な `assessment_mode=shadow` のときだけ追加し、既定は `off`。
- 発話行為の観測は推定であり、引用が確認済みの回答Transcriptに一致する場合だけ有効とする。設問と回答の対応を推測で確定しない。
- 基準未登録でも観測は残すが、達成度は保留する。基準の規則なし・複数一致も保留する。
- 生音声をJudgeへ送らない。音声直接入力は将来の独立した比較実験とする。
- APIと新しいターミナルコマンドは同じ評価サービスを使う。既存の対話式ターミナルは変更しない。

## 設計

既存経路は `EvidencePipeline` → ５つの独立したFact Module → 既存Judge・協議 → 従来結果のまま維持する。別枝で `TaskContext v1` を組み立て、確認済み回答があれば観測専用AIから `TaskObservation` を得る。観測は発話引用・Transcript上の位置・モデル来歴を持ち、達成度を含まない。版付き `TaskRubric` がある場合だけ純粋関数 `apply_rubric` で `TaskAssessment` に変換する。

基準未登録なら `rubric_unavailable` と観測を返し、評価値は返さない。観測失敗、対応未確定、基準競合は別の状態を返す。新経路の失敗は既存結果を失敗させない。複数設問では確認済み回答ごとに独立した結果を返す。旧 `task_rating` は録音全体の値なので、設問別の新結果と同じJSONに並べても自動で一致率を計算しない。

ターミナルの `evaluate-speech` はAPIと同じ `evaluate_speech_level` を呼ぶ。`--assessment-mode shadow` と `--task-context-file` により試験経路を明示し、`--output` で旧結果と新結果を一緒にJSON保存できる。Mock Judgeは疎通確認専用であり、実際の発話観測や正式な達成度として扱わない。

## 作業と検証

1. [x] `TaskContext`、引用検証、版付き基準、保留状態を追加。
2. [x] APIの既定 `off` と試験用 `shadow` を分離し、従来結果を上書きしない。
3. [x] 基準未登録でも確認済み回答の観測を保持する。
4. [x] `evaluate-speech` でAPIと同じ経路をターミナルから使い、JSON保存できるようにする。
5. [ ] 実データで観測精度、ASR誤り、設問・回答対応、モデル差、費用・遅延を測る。人手ラベルと採用条件が決まるまで正式採点へ昇格しない。
6. [ ] 話者分離や時刻付き文字起こしはInteraction／共通層の独立した拡張として検討する。
7. [ ] 音声直接入力は、提供者・コスト・音声データ管理を比較した別実験にする。

## ロールバック

`assessment_mode=off` なら追加AI呼び出しを行わず従来経路だけが動く。新コマンドを使わなければ既存の対話式ターミナルにも影響しない。
