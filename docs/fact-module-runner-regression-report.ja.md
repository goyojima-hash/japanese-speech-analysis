# 共通 Fact-Module Runner バグハンターレポート

## 再現した回帰

API は `coherence` を選択できましたが、対話ターミナルは Range と Accuracy を直接呼び、Coherence を選択していませんでした。そのため、ターミナルには Coherence 表示も Judge 入力の `coherence_data` もありませんでした。

## 5 Whys

1. なぜターミナルに Coherence がなかったか。ターミナルが独自のモジュール実行を持っていたため。
2. なぜ独自実行を持っていたか。API とターミナルが事実パケットを別々に組み立てていたため。
3. なぜ危険か。モジュール追加ごとに二箇所を手作業で変更する必要があるため。
4. なぜ漏れたか。テストが個別のターミナルパケットだけを確認し、共通実行契約を確認していなかったため。
5. なぜ再発しないか。両方が `run_fact_modules` を使い、選択パケットの伝播とターミナル Coherence 出力をテストするため。

## 特性要因と対策

| 原因領域 | 対策 |
| --- | --- |
| アーキテクチャ | 一つの runner がモジュール検証と収集を担当 |
| 統合 | `FactModuleRun` が選択パケットを客観データと Judge データへコピー |
| 互換性 | API デフォルト選択は維持 |
| ターミナル | 同じ runner を使う全実装済みモジュール表示プロファイル |
| テスト | RED runner／ターミナル Coherence テストと全回帰スイート |

## タイムライン

1. runner 不在とターミナル Coherence データ不在を RED テストで再現した。
2. 共通 runner を追加し、API／ターミナル呼び出し元をリファクタリングした。
3. 任意パケットデータから Coherence のターミナル表示を追加した。
4. 集中テスト、全テスト、コンパイル、空白チェックを確認した。

## 再発防止

API とターミナルのどちらも Range、Accuracy、Coherence を直接収集しません。新しい事実モジュールは `fact_modules.py` に一度だけ登録・収集され、両方の入口は同じパケット機構で受け取ります。
